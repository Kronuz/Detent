## Answers to the lead's questions

1. Crash safety. Fetched files are written as `.tmp-`, linked, and then synced with the directory as one group. The table goes through `.tmp-`, fsync, rename and a directory sync. The collector runs after that, and startup removes orphans and `.tmp-` files. The repair path writes, fsyncs, renames and syncs the directory. All of these are correct, and the matrix cuts after each of them, including the removals (collect, remove orphan, remove temporary, unlink temporary). The exceptions are the EEXIST relink, which is both unsafe and never cut (D1), and `clean()`'s removals, which are uncut but safe (unreached `.tmp-` names).
2. Byte identity. Yes. The relays' disks and tables are compared against the real voters at A, B and C, and the frames against an oracle (relying on 261113-003843-d3ad47 and the mutants above). The voter's own W6 is test-side until the authority exports it (journal ruling 11).
3. Restart. No file is re-fetched (measured, as above). Nothing can be applied twice, because the ring is keyed by position and frames are applied only after the body decodes whole. The ring itself is re-read by design (D6). A restart on an upstream relay can still make a downstream lose its whole mirror of a namespace and re-fetch it (D2).
4. Cut and policy changes. Yes, for the adoptions the tests drive: the collector removes exactly the names in the previous reached set minus the new one (`mirror.cc:454-470`), and `mirror_matches` holds at every step and in every recovered cut. D1 is the one recovered state that keeps a reached name with the wrong bytes.
5. The equivalence holds. `PosixIO::remove` has one POSIX implementation, `unlinkat(...) && errno != ENOENT` (completion:560c288 `include/completion/posix.h:564-567`), with no per-platform branch. The mirror is POSIX-only (`linkat`, `geteuid`), and CI runs only on ubuntu-24.04. With the check, a missing name is skipped and any other name is removed; without it, a missing name gets ENOENT, which is ignored. Any other errno throws in both versions, as `inspect_entry` throws on errors other than ENOENT. `collect_missing` passes without the check on macOS in 261113-003843-d3ad47. Linux is CI's, and the branch is not pushed yet.
