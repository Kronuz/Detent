- Blocked on: damaged-pack repair (needs a lead ruling; nothing built).
  - **What triggers it.** (1) The scrub finds a pack whose SHA-256 differs from its owner record (`CoordinatorStatus::scrub.source_failure`, `damaged_packs`). (2) A first-touch failure in the update path or in the recovery after a publication (`ReadSourceFailure`, "local page failed first-touch verification"). Today (1) is reported (status, agent log) and counted as a coordinator failure; (2) fails the publish call (the writer-level test shows the throw); no coordinator test covers what the coordinator does with it.
  - **What it should do (D10.3).** Fail that namespace alone (today: the whole store, one generation): reads of the damaged pages already return `SourceFailure`. The agent then asks upstream for a Replace and publishes a fresh generation that contains no page of the damaged packs, at the next build ordinal so no durable file is touched; the collector then removes the damaged packs, which nothing reaches.
  - **What is missing for that on today's store (C2, random ids).** Evidence: in `test_testing_trusted_restart_t5` a republication over a base with damaged packs reached a new revision whose every read was correct while the damaged packs were still on disk, so a snapshot publication that changes content did not carry damaged pages forward there. It does not follow that a repair is guaranteed: a Replace whose content equals the base is detected as unchanged and publishes nothing (`PagedSnapshotPlanBuilder::unchanged`, `coordinator.cc` `build_paged`), and I did not trace whether the snapshot plan can reuse a base segment in other cases (`paged_reuse.cc`, `paged_contextual_reuse.cc`). The coordinator has no repair state: `force_snapshot` only changes the upstream request; a damaged-pack report does not request one; and a first-touch failure in the recovery after a publication fails that recovery (the publish call threw in the test) instead of being repairable. The fresh names that make a repair safe against a durable `selected` come from the build ordinal (D8.2), which does not exist until S7; with random ids a fresh copy is new names anyway.
  - **What I need from the lead.** One of: (a) defer repair to S7: until then a damaged pack is reported by the scrub, its reads fail, and the next restart of a store whose pack is damaged is not refused (the pack is mapped, not hashed), so the operator's repair is to bootstrap a fresh store; (b) authorize the repair now: the coordinator requests a Replace when the scrub reports a pack or a first-touch failure occurs, forces a publication even when the content is unchanged, passes the damaged segment ids to the snapshot plan as segments not to reuse (an `excluded_segments` input to `PagedSnapshotPlanBuilder` and its reuse, if the trace shows reuse can happen), and treats the post-publication first-touch failure as repairable; the collector then removes the packs. This is a new mechanism in the coordinator and the plan, and a change to D10.3's "next build ordinal". I recommend (a): D8 ties repair to ordinals, S7 builds them, and (b) would be rebuilt there; I would trace the reuse question first if you choose (b). The scrub's report and the first-touch failures already give the operator the signal.

- Design vs code:
  - D10 says restart is O(namespaces) with packs opened on first use. The agent's code needs a registry and per-segment reachability that only a walk produced; shape A stores them in `.live`, so a restart is O(segments): per segment one `.owner` read, one stat and one `mmap`, no pack read, no hash (the census already did the reads).
  - D10.2 puts a manifest digest in `.read` (W12). Per the lead's ruling the manifest is `.live`'s rows and its trailing digest; `.live` binds to `.read`'s own digest and `.read` binds to the root, in place of the table binding the `.read` digest (today's `selected` has none).
  - The design names "the table"; today's store has the 176-byte descriptor, so S3 binds what exists.
  - The first-touch accessor has nine read sites, not eight.
  - The refusal of a store without `.live` applies to the agent's cold start (`RecoveryContext::trusted_start`). The full verified recovery stays for the recovery after a publication (S4 drops it) and for `recover_generation` and the tools that call it.
  - A republication over a damaged base builds from the incoming snapshot and can reach a durable generation that shares no damaged page; the recovery after it then fails first touch (the coordinator would fence). The test accepts either revision.
  - The coordinator's "republish a missing `.read`" branch is unreachable from a cold start now that a store without `.read` is refused; `test_prepared_startup` and `test_prepared_republish` start from stores that have both records instead. The branch is left for the lead to remove.
  - `DiskLedger::paged_peak` takes the live record's size; the disk quota estimate gains one entry and the record's bytes per generation.
