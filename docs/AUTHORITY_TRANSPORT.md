# Authority transport implementation

**Status:** Bounded peer listeners, authenticated control/bulk lanes, HTTPS and fixed-voter configuration are implemented under the [validated service blueprint](ASYNC_AUTHORITY_ARCHITECTURE.md). Three-process failure and scale acceptance remain open.

The transport code lives in `src/detent_authority/transport/`. It depends on the strict consensus types and OpenSSL 3.0 or later, without modifying the legacy cluster protocol or existing durable encodings. The optional authority build links these primitives through `detent_authority_transport`; the daemon selects HTTPS when `publisher_tls` is configured. Replicated configuration requires HTTPS and peer mutual TLS; the existing single-voter loopback profile remains available.

## Admission and encoding

`DTHL0001` is a fixed 120-byte peer hello carrying the node ID, control/bulk lane, cluster/group/restore epoch, fresh 128-bit connection identity and 256-bit semantic fingerprint. Certificate admission establishes voter identity independently of the hello. The fingerprint includes the canonical application limits, consensus limits and sorted fixed voter membership; it excludes the local voter ID. A different quorum or application profile fails admission before replication payloads are accepted.

`DTC1` uses explicit stable control tags and little-endian integers. Booleans, entry kinds, snapshot correlation, counts and trailing bytes are checked. Entry counts are bounded before vector allocation; both per-command and aggregate payload limits apply. Raft's `rpc_bytes` limits payload rather than framing, so the checked maximum Append wire size is `68 + 32 * rpc_entries + rpc_bytes`, before the outer four-byte length prefix. A full legal 2 MiB payload round-trips.

Peer TLS requires chain verification and a SHA-256 leaf-certificate pin bound to one configured voter. Configuration checks reject duplicate pins and a local certificate that differs from the local voter pin. Publisher clients verify the chain and requested DNS name or IP address; publisher servers retain the separate application credential check. The service computes configured credential digests once at startup and compares every configured digest on each request, preserving the existing full scan. The digest cache uses 32 bytes per credential; it changes neither the credential format nor producer authorization. TLS versions below 1.2, early data and renegotiation are disabled. Certificate-list admission is capped at 64 KiB.

## Owned operations

The session belongs to one authority executor. It retains its TLS context, allows one original read and one original write, and rejects application operations before authenticated admission. Handshake and hello exchange share one absolute deadline. Idle bulk lanes can remain open; after the first frame byte, one absolute header/body deadline prevents trickled input from extending the wait. Whole writes have a finite deadline.

`Frame` acquires shared byte credit before allocating its buffer and retains it through original write completion. Cancellation races reap the losing original operation before releasing that buffer. Socket error shutdown closes the transport; it does not start TLS shutdown concurrently with application IO.

`SnapshotWrite` copies SnapshotChannel's borrowed frame into owned write storage. Closing, fencing or timing out the channel cannot free those bytes during a suspended TLS write. Successful completion consumes channel output only when the trusted session, token and remaining length still match. An obsolete completion releases its own resources without consuming a replacement connection's frame. A socket write never synthesizes an Installed acknowledgment.

The [retained admission API](../../Kronuz/cluster/consensus/README.md) supplies the additive Worker API needed to hold one decoded control event through Busy/Pressure without copying its payload on each retry. It is committed in cluster `10de37c`; the existing API and storage/wire formats remain compatible.

## Qualification and remaining work

The transport tests use real TLS records over both OpenSSL BIO pairs and asynchronous duplex pipes. They cover mutual authentication, unknown CAs, missing client certificates, unknown and duplicate voter pins, incompatible profiles, hostname verification, oversized/zero/partial frames, exhausted byte admission, stalled writes and shutdown with original reads/writes pending. Explicit coroutine cancellation preserves an operation-aborted result rather than misreporting a deadline. Pipe tests qualify the asynchronous stream contract and cancellation mechanism, not a TCP deployment. Snapshot ownership tests retire the borrowed allocation while its owned copy remains charged and reject stale session/token/offset completion.

The four transport suites and certificate fixture pass natively (3.70 seconds) and under ASan/UBSan (4.03 seconds) with OpenSSL 4.0.3. Directly compiled authentication and asynchronous pipe tests also pass with OpenSSL 3.6.5. The full application build succeeds; a broader selection passes 23 of 24 suites, with the TCP diff-cache test unable to connect to its local server. Existing authority state, both Node/cluster scheduling profiles, service and process-recovery tests pass. These results do not replace the complete-component acceptance gates.

The real TCP test remains registered as `test_authority_transport_tls`. After restoring session permissions, it passes over real loopback TCP (2.76 seconds including certificate setup). Authenticated three-process failure/scale tests remain unqualified until service integration is complete. The earlier permission-limited run could not bind TCP and could not connect to the diff-cache server; those failures do not qualify network behavior.

The peer runtime now supplies bounded incoming handshakes, per-voter control/bulk lanes, deterministic lower-ID dial ownership, authenticated reconnect generations, retained Worker admission and SnapshotChannel dispatch. Shutdown closes pending connects and active streams, then retains the runtime until original operations are reaped. The optional shared HTTP TLS adapter retains one owned plaintext read across deferred reply writes and returns a pipelined byte to the parser. Incremental consensus CPU work and other-platform native qualification remain separate open gates. Review the complete service after these gates pass; this module is not Stage 4 completion.

The latest native qualification passes all 38 existing Detent tests (50.53 seconds), all eight service/transport checks including follower transport replacement (10.72 seconds), and all five HTTP-library regressions (3.60 seconds). The real HTTPS deferred-reply test preserves a pipelined request byte across the suspended reply (0.68 seconds including certificate generation). These are component-level fixtures; they do not establish three-process failover or fleet scale.

The initial replicated service timing profile uses a 100 ms heartbeat, 500 ms RPC deadline and randomized 1000–2000 ms elections. Three separate HTTPS daemon processes pass durable Open/CAS, exact receipt retry, leader SIGKILL, post-failover strong reads and recovered voter reconnection. The previous Core fixture defaults (100–200 ms elections and 40 ms RPC deadline) repeatedly left all three native-storage processes campaigning with authenticated lanes. Both timer classes changed together, so this experiment does not isolate their individual contributions. Production latency and load qualification remain open.

Control readers now retain one event per connection and suspend until a bounded owner round-robin pass admits it. Each pass admits at most one event before servicing Node completions and timer/maintenance debt. Busy ends the pass; Pressure can skip to another peer. The synchronous fixture now configures an election maximum that covers every supplied Tick, correcting the earlier comparison in which two voters received invalid delays.

The shared-library ownership fixes are committed separately: reactor `863bed0` reaps original sessions before stopping loops; HTTP `70cf14f` joins streaming handlers before releasing request storage, and `708f457` adds the optional TLS adapter and owned read-ahead. Native reactor tests pass 3/3 (2.15 seconds), sanitizer reactor tests pass 3/3 (2.74 seconds), and HTTP passes 5/5 natively (3.73 seconds) and with ASan/UBSan (4.59 seconds).

The complete current Detent suite passes 41/41 natively (65.28 seconds). The snapshot fixture reconnects a follower after both available voters have compacted their logs and requires a nonzero installed snapshot boundary, rather than accepting ordinary log replay as snapshot evidence. The real three-process fixture discards an original transaction response after a strong read proves commitment, retries the transaction, kills its leader, reads from the new leader and restarts the killed voter. HTTPS and that process fixture pass with ASan/UBSan (6.85 seconds including certificates). These gates do not establish platform-wide native support, load capacity or Stage 4 completion.

## Fixed-voter configuration

Every new group uses fresh independent stores and the same cluster/group/epoch and fixed voter list. Each voter entry contains its nonzero `id`, literal-IP `host`, peer `port`, and a 64-digit SHA-256 fingerprint of its leaf certificate's DER encoding. The root `node` selects this process. `peer_tls` and `publisher_tls` each contain `certificate`, `key`, and `ca` paths resolved relative to the configuration file. Replicated configuration requires both TLS objects. Credentials retain the existing producer/namespace authorization format. `publisher_bind` selects the publisher listen address (loopback by default), and `publisher_name` selects the verified certificate name used by daemon status (`localhost` by default). Non-loopback binding requires TLS. `detentd --status --authority CONFIG` checks HTTPS with CA/name verification, a 64 KiB response bound and one two-second network deadline; wildcard listeners are probed over their local loopback address.

Configuration files remain regular, owner/root-owned files without world access or group/other write permission. Editing the voter list of an existing store is rejected by durable recovery; fixed membership has no implicit migration. Export/import into a new group and restore epoch when changing membership.

Snapshot transfer and catch-up also pass under ASan/UBSan (8.02 seconds including certificate setup). The publisher TLS adapter now retains global connection credit through original session completion, including idle authenticated connections; its separate handshake credit retires after admission.

The Linux authority now integrates the owned io_uring completion queue with explicit setup policy and native/fallback health counters. [Linux completion storage](LINUX_COMPLETION.md) records its capability boundary and qualification in progress. Startup/recovery remain synchronous; complete-stage acceptance is still open.

Publisher task and deferred transport deadlines use the same captured outcome deadline. The transport retains one additional second for writing the bounded response after outcome timeout. This prevents the transport timer from discarding the authority's retryable 503 at the instant it becomes ready. Original writes still retire before reply and request credits are released; an admitted command whose outcome remains unknown must be retried with the same identity.
