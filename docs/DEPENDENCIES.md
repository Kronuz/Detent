# Reproducible dependency sources

[CMake's dependency manifest](../cmake/dependencies.json) records immutable revisions for direct and transitive fetched libraries. `DependencyPins.cmake` declares them before any library populates its own dependency graph, so FetchContent's first declaration wins consistently across authority, relay, managed-agent and reader builds. Changing the manifest triggers configuration again.

Profiles populate only the libraries they need. The manifest also pins the optional LZ4 and Zstandard source fallbacks; installed compression and TLS libraries remain system dependencies. The system-library discovery policy is unchanged. Record compiler, SDK/OS and system link inputs when reproducing a binary; source pins alone do not establish a hermetic toolchain.

The manifest holds 35 entries: 30 Kronuz libraries at their default-branch heads as of 2026-11-04 (M1) and asio, cppcodec, RapidJSON, LZ4 and Zstandard. Every Kronuz pin is outside the ranges of "Commits not to pin" in cpp-libraries' [upgrade guide](https://github.com/Kronuz/cpp-libraries/blob/main/docs/UPGRADING-2026-10.md), and `tools/check_pins.py` (CI job `pin-check`) fails when a pin differs from the pin of a library that declares the same dependency, so FetchContent's first declaration never hides a different revision. Pins move dependency first, as the guide's "Updating an application" lists; [DEPENDENCY_UPGRADES.md](DEPENDENCY_UPGRADES.md) records the M1 move, with the old and new pin of every library.

A clean native configure fetches the entries its profile needs (authority, relay, managed agent, benchmarks) from public repositories with no sibling overrides. The libraries the build links are listed in [Dependencies](../website/src/content/docs/architecture/dependencies.md).

Developer overrides remain available through CMake's `FETCHCONTENT_SOURCE_DIR_*` variables. They override the manifest and can point at changing sibling work. Use immutable archives or detached checkouts for qualification. The system runner records actual Git revisions and content fingerprints rather than assuming an override matches the declared revision. Its build-source fingerprint distinguishes a copied source snapshot from an enclosing Git repository.

Detent no longer depends on cpp-btree. The model tables use [Kronuz/flat-map](https://github.com/Kronuz/flat-map) at the manifest's immutable revision through `detent::flat_map`. The local header supplies names only; the implementation and generic tests belong to the library; see [Container selection](CONTAINER_SELECTION_ARCHITECTURE.md#decision-october-23).
