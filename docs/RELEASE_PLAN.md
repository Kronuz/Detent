# Initial release qualification

**Updated:** 2026-10-22. **Status:** Stage 6 active. The owner includes the remaining reusable-library extractions before release.

The initial release supports a regional fixed three-voter authority, durable relays and host-local last-known-good readers. Implementation acceptance for earlier stages does not establish sustained capacity, complete restoration or deployment qualification. Release requires the gates below; passing short transport probes does not certify a fleet of durable agents.

Finish dependency-only comparisons before mixing extraction changes into their application source. Extract one mechanism at a time into its existing library where one fits; create a small library only when the catalog has no suitable owner. Preserve public interfaces and valid wire/disk bytes, and update the cpp-libraries index with each extraction. Generic daemon plumbing needs a demonstrated shared consumer; otherwise retain it in Detent and record that decision.

The [shared resource blueprint](RESOURCE_EXTRACTION_ARCHITECTURE.md) establishes optional targets in `allocators`. The resource libraries are published; isolated Detent integration removes its private allocation, retirement and DiskLedger accounting bodies. The [HTTP client blueprint](HTTP_CLIENT_EXTRACTION_ARCHITECTURE.md) defines the next component, followed by the [bounded MessagePack component](MSGPACK_EXTRACTION_ARCHITECTURE.md) and the persistent map. The bounded `msgpack` target must configure without fetching its DOM dependencies; client-only HTTP targets must preserve optional server and TLS dependencies. Each component removes the migrated private implementation and receives one complete review.

Resource extraction preserves the difference between automatic memory refunds and explicit durable disk settlement. Task scheduling, mapped-file residency and transfer helpers are reuse evaluations, not blanket replacements for Detent's protocol and ownership state machines. No release requires inventing a general framework around application-specific machinery.

Use complete-component architecture reviews and final implementation reviews rather than per-commit approvals. Track C may finish transport while Detent completes independent extractions; intermediate v2 revisions remain excluded from adoption. Final integrated qualification follows all selected source and pin changes.

The active dependency gate is [btree qualification](BTREE_RELEASE_RISK.md). The [original combined transaction blueprint](BTREE_EXCEPTION_SAFETY_ARCHITECTURE.md) remains a historical design after its failed cost gate. The first guarded copy draft increases retained container bytes by 27.27% for populated copies and 78.25% after pruning, so it is excluded from adoption. The replacement compact builder and insertion transaction pass the original Linux publication LeakSanitizer sweep and three-platform library profiles. The complete erase/drain draft passes three-platform and composed LeakSanitizer gates, but matched mutation CPU is about 5.75 times baseline with excessive allocation churn. Seven independent corrections are published and adopted at `cbc3576` after 207/207 product tests. The [localized compact-root growth repair](BTREE_COMPACT_ROOT_ARCHITECTURE.md) passes three-platform, publication-failure and shared CI qualification. The independent nonfull append accounting fix has three-platform and seven-job hosted qualification; its all-product Release build and full native suite pass in 624.81 seconds. The [nonfull-leaf insertion component](BTREE_NONFULL_INSERTION_ARCHITECTURE.md) uses a revised prepared construction design after the first replacement prototype fails its cost gate; it passes source/cost review, seven hosted jobs and the all-product rebuild with 207 tests (630.01 seconds). The [ownership-move component](BTREE_OWNERSHIP_MOVE_ARCHITECTURE.md) passes the platform, hosted and clean all-product gates with 208/208 tests. Construction retained bytes match, but genuine moves preserve capacity: pruned short-key final snapshots retain approximately 13.3–13.5% more requested heap than the old compact-copy behavior. Adoption is held for the [container comparison](CONTAINER_SELECTION_ARCHITECTURE.md); further [structural insertion work](BTREE_STRUCTURAL_INSERTION_ARCHITECTURE.md) is on hold. The [capacity qualification](CAPACITY_QUALIFICATION.md) targets 5M knobs, with 10M exploratory tier and explicit runtime-limit work. The transaction rewrite remains unpublished. Final product qualification remains open. See [dependency qualification](DEPENDENCY_UPGRADES.md) for source attribution, reviewed boundaries and current evidence.
