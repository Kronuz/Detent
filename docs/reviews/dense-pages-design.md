## Verdict

**APPROVE WITH REQUIRED CHANGES.** The dense layout, placement-free commitment and subtree-local packing rule are a sound direction. DP-1 through DP-3 settle contracts the implementation builds on; close them before implementing the affected reuse, root and validation paths. DP-4 through DP-6 are implementation and landing conditions. No benchmark improvement is established here.

Keep the whole-pack checksum, Q1(a), throughout S1–S5. Keep record full copies, Q2(a), throughout S1–S5. Both preserve the current delivery design; changing the full-copy frame remains a separate owner decision.

## Findings

1. **DP-1 — Builds on: distinguish a page occurrence from its digest in delta reuse and the oracle.** D7 promises that a delta writes exactly the pages its base lacks, while specifying reuse by the corresponding base placement (`docs/design/dense-pages.md:156`). T4 defines the difference by digest (`:212`). The oracle stores one length per digest (`docs/design/dense-pages-model.py:780`, `:850`) and treats every target occurrence whose digest appears anywhere in the base as reusable (`:1324`). Those are different contracts.

   Equal digests do not identify one trie occurrence. For example, `Kns\0x\0` and `Kns\0y\0` can have identical valid definition bodies and revisions. Their leaf suffixes after the branching label are both `\0`. If the bodies exceed the 4 KiB cluster budget, both leaves seal alone and encode identical page content at distinct placements. Definition encoding contains revision and value, not the key (`src/detent_local/paged_definition.cc:37`, `:63`); the model seals and hashes exactly that suffix/body (`docs/design/dense-pages-model.py:677`, `:797`, `:844`). This requires no SHA collision.

   D9 retains physical disjointness (`docs/design/dense-pages.md:166`): pointing two logical occurrences at one physical extent is rejected by the current cell marking (`src/detent_local/paged_graph_validator.cc:265`). A newly sealed clean cluster may also match a base page elsewhere; digest membership alone cannot say whether that extent is already needed by another occurrence. The current model never executes an incremental allocator, so its full-build set difference does not prove the promised delta writes.

   Required change: retain tree occurrences and specify reuse by corresponding logical subtree/path plus digest, with each physical extent assigned at most once. State which newly sealed clusters can reuse a base extent and which must be written even when an equal digest exists elsewhere. Make the oracle compare occurrences and multiplicity, and report digest-set novelty separately from actual newly written pages. Alternatively, a shared-page DAG needs a separate design for counting, disjointness, collection and bitmap assumptions; it is not implicit in this draft. Add repeated-content fixtures, including a clean cluster newly sealed beside an equal page already retained by another path. Recompute T4's exact targets if this changes them.

2. **DP-2 — Builds on: complete DTROOT03's empty-state and reserved-byte contract.** D3 removes the root's separate logical digest and says all consumers read the root page's digest (`docs/design/dense-pages.md:49`, `:84`), but a legal empty state has no root page. Today's root validator explicitly accepts zero records, namespaces, pages, bytes and segments, with an empty tree and `empty_commitment()` (`src/detent_local/paged_layout.cc:65`); the overlay uses that commitment when deletion empties the tree (`src/detent_local/paged_overlay_assembler.cc:303`). Removing `detent.local.logical.v2` in S5 also removes its current empty-state domain (`src/detent_local/paged_layout.cc:187`). Neither the new value nor its API meaning is specified. The oracle starts by reading key 0 (`docs/design/dense-pages-model.py:399`), so it does not cover this state.

   Required change: define the empty commitment, its representation in `Reference`/`Root`, and what every state-equivalence consumer returns for it. Specify the DTROOT03 version field and the zero-reserved range after the 65-byte reference at offset 160, including the old logical-digest bytes. Require zero reserved bytes on decode, as the present root decoder does for its reserved tail (`src/detent_local/paged_layout.cc:283`). Add exact root/reference fixtures and tests for an initially empty store, deleting the last definition and namespace, restarting empty, and adding the first namespace again. A watermark-only store does not cover empty.

3. **DP-3 — Builds on: bind every external summary to the page it describes.** The new reference adds key count and height to its digest and length. D4 compares the hash and checks the page's own aggregate height, but never explicitly requires the reference's keys and height to equal the reached header (`docs/design/dense-pages.md:84`, `:90`). D9 then makes sealing decisions from those external summaries (`:166`). A parent with a recomputed valid digest can advertise a false child height; the child can independently have a valid digest and correctly computed header height. The two local checks do not reject their disagreement. The same issue applies to a warm validator that skips a reused subtree and accepts its new summary solely because its digest matches.

   Required change: specify equality of reference and page header for length, keys and height at graph validation and first touch. Specify the trusted evidence a warm validator uses when it skips a page. When replaying D5, a normal sealed child's candidate cluster has size `length - 64` and height `page_height - 1`; a child sealed by itself above C is not a candidate to inline. State that distinction and checked arithmetic explicitly. Add checksum-correct malformed fixtures for false keys, false height, zero height, height overflow and an oversize self-sealed child. The false-height fixture must exercise a competing sealing choice, so deleting the cross-page equality check makes a canonicity test fail.

4. **DP-4 — Carry S3b's verified-mapping ruling into the dense walk and state the detection limits precisely.** D4's compare detects redirection to a page whose header digest differs; it does not rehash that page's contents (`docs/design/dense-pages.md:96`). Rewriting a verified page's node tag, node count, slot, suffix length or body length can still change traversal or make unchecked reads escape the mapped span while leaving the header digest intact. A rewritten placement can also steer into a different offset in an already verified bitmap granule. The current S3b review already establishes read-time bounds as an open owner question (`docs/reviews/namespace-s3b-architect-2026-11-04.md:27`, `:85`); replacing the whole walk must preserve its resolution. Restoring the digest compare does not undo the entire mutation limitation in reader Limit 5.

   Required change: carry S3b C1 and the owner's ruling explicitly into S3. If the bounded-read option is chosen, bounds-check each field and slot used by the walk on every visit, including bitmap hits; bound traversal progress under a changed slot so a verified-page cycle cannot hang the caller. Translate malformed reads to the selected source-failure behavior. Test mutation after verification separately from initial corrupt bytes: node framing, external-table arithmetic, an in-page slot back edge and a placement into the interior of a verified granule. Preserve the documented residual for undetectable value changes until scrub. The owner may retain the current mutation behavior; this review does not make a narrowing of user-visible behavior a prerequisite. In either case, revise S3's unconditional “a damaged read fails, and none returns a wrong value” (`docs/design/dense-pages.md:329`) to match the chosen threat model.

5. **DP-5 — Make the proof rows executable and reconcile their dependencies and counters.** The ledger contains no lead-set done criteria (`docs/status/dense-pages.md:8`), despite the draft's detailed S1–S5 checklists. Three row definitions cannot currently be executed as written:

   1. T1(2) requires identical files during S2, but D5 conditions file identity on namespace S7's derived ids, which the landing table calls independent (`docs/design/dense-pages.md:113`, `:289`, `:312`). Gate S2 on placement-free page identity and the specified seal-order offsets; gate complete file identity on T8 after S7. State which identity inputs, including cursor/profile/build ordinal, must be equal.
   2. T6 expects `bytes_hashed` and `page_digests()` to report page input plus segment checksums (`docs/design/dense-pages.md:214`). SegmentBuilder feeds its SHA directly and increments neither counter (`src/detent_local/paged_segment_builder.cc:13`, `:80`, `:89`, `:105`). `bytes_hashed` is currently charged in `verify_page`, not the builder (`src/detent_local/paged_layout.cc:170`). Conversely, root descriptor hashing calls `physical_commitment` and increments the page counter (`src/detent_local/paged_overlay_assembler.cc:319`). Define separate page, pack and metadata counts, with an exact measurement boundary and expected totals for each; instrument builders as well as validators. T7's “no page digest” must exclude its necessary root/descriptor hashing by definition, not by accidental counter placement.
   3. T1's command uses churn's implicit mixed-churn default (`docs/design/dense-pages.md:209`; `docs/design/dense-pages-model.py:1498`), while T4 has two different exact targets. Publish complete commands with explicit U/I/D for the one-update and mixed-churn targets, the corpus digest, revision bump/seed and model revision, and preserve their raw outputs. For any oracle lacking a required operation, name the C++ property test that supplies it; the current model computes two full builds rather than an incremental delta.

   Required change: the lead sets numbered criteria covering S1–S5, these corrections and the carried findings. Keep exact counts as projections until reproduced. Add explicit cancellation/admission and bounded-memory checks for retained open clusters and resumable validation; the present assembler charges and yields through `ValidationBudget` (`src/detent_local/paged_overlay_assembler.cc:82`, `:124`), and a synchronous pure packer must not silently bypass that contract. Require separate ASan+UBSan and TSan evidence where the changed read/bitmap paths involve threads, checksum-correct fuzz inputs for both validators as well as first touch, and live assertions or explicit checks in fuzz/property builds. T10 names validators but its stated harness only names first touch and walk (`docs/design/dense-pages.md:218`).

6. **DP-6 — Make the reader result a landing gate with a quantitative baseline.** T5 inherits useful concrete targets from reader T1 and T2, but S3 and the after-landing plan defer it until after S1–S5 switch the only format (`docs/design/dense-pages.md:270`, `:332`, `:362`). D4 adds a compare to every page hit and D6 projects a larger first-touch cost; neither has a measured acceptance result. Measuring exclusively after the irreversible-for-old-stores switch leaves no accepted format if the reader gate fails.

   Required change: capture the preceding main/S6 baseline and run T5 on the complete candidate before merging; repeat the accepted measurement on main for attribution. Specify the reference platform and pinned-view/S3 baseline commits, the scattered verification counts, the existing 200/200 below 1 ms first-read target for both namespace counts, and how a miss is handled. Build CPU/wall in T6 may remain informational: do not present the “at most about 108 s” estimate (`docs/design/dense-pages.md:197`) as a proved upper bound. The 4 KiB choice is provisionally sound on bytes and hops; acceptance also needs actual reader measurements.

## Decision rulings

| Decision | Ruling | Reason / required condition |
| --- | --- | --- |
| D1 One digest, placement outside | Sound with changes | A Merkle commitment over canonical content permits relocation; DP-1 and DP-3 specify reuse identity and summary validation. Whole-pack checksums remain. |
| D2 Binary layout | Sound with changes | Two-byte slots suffice for the 4 KiB format's inline branches; oversize leaf pages have no slots, and oversize branch pages remain below 32 KiB. Require exact fixtures and DP-3's bounds. |
| D3 Reference and root | Sound with changes | DP-2 specifies the missing empty state and reserved bytes. |
| D4 First touch and hit | Sound with changes | The hit compare is required by unauthenticated placement. DP-3 binds summaries; DP-4 carries mutation behavior without overstating detection. |
| D5 Bottom-up canonical packing | Sound | The model orders candidate clusters by `(height, -size, label)` (`docs/design/dense-pages-model.py:645`) and emits seals in that order (`:708`). This depends only on subtrees. Page membership of an inline descendant also depends on ancestors: only the cluster rooted at a node is subtree-local. |
| D6 4 KiB capacity | Provisionally sound | The projected byte/hop trade is explicit, including scattered-write amplification. DP-6 supplies the missing measured read acceptance. |
| D7 Delta repacking | Sound with changes | Boundary changes require reading newly inlined children and sealing clean off-path clusters. DP-1 replaces the insufficient digest-membership write oracle. |
| D8 Digest-free relocation | Sound | Only placement changes, so page digests and root commitment remain fixed. T7 must also compare all values, graph counts and live accounting after partial and complete relocation, not only its root digest/counter. |
| D9 Canonical validation | Sound with changes | Local replay plus validated child summaries can support induction. DP-3 supplies the cross-page induction premise. |
| D10 Recovery and other consumers | Sound with changes | Keep the pack checksum and record delivery. Preserve trusted-restart/first-touch/scrub separation and the S3b rulings in DP-4. |

## Gate and criterion coverage

1. **T1–T4:** Useful exact shape/size/churn targets; add DP-1's repeated-content occurrences, DP-2's zero-record state and DP-3's checksum-correct invalid summaries. The 5M mixed-churn off-path assertion is explicitly not rerun on the final model (`docs/status/dense-pages.md:19`); its exact target remains projected.
2. **T5–T6:** Concrete inherited reader targets, but DP-5 fixes measurement observability and DP-6 moves acceptance before landing. CPU/wall may be recorded without a speedup target.
3. **T7–T8:** Preserve values and live accounting after relocation; complete file identity waits for derived ids. Neither root equality alone nor digest sets prove physical accounting.
4. **T9:** Test both DTROOT02 refusal and a DTROOT03 envelope that reaches a DTPAGE02 page, plus interruption/restart during the replacement full copy. A failed copy must stay unavailable and retry; it must not serve old bytes as version 3.
5. **T10:** Cover graph/warm validators, placement arithmetic and resource/hang limits, not only a fresh page walk. Mutate a verified mapping separately: rewriting a fresh input's digest is not that test.
6. **S1–S5:** A workable single-series order once the three builds-on contracts are fixed. The lead must adopt the criteria in the ledger, carry S3b's conditions forward, and make T5 plus required sanitizer/proof results prerequisites to landing. The handoff's explicit CI dispatch supersedes the draft's claim that every proposed branch prefix triggers CI automatically (`docs/design/dense-pages.md:270`).

### Status per finding

1. **DP-1: Design contract closed; allocator proof open.** D7 defines one entering trie path plus equal digest/length/keys/height, and assigns each retained extent once (`docs/design/dense-pages.md:164`). The model preserves those paths at cluster creation and seal, then compares occurrences and rejects duplicate base ownership (`docs/design/dense-pages-model.py:671`, `:700`, `:754`, `:1419`). Digest novelty is reported separately (`:1373`).

   This composes across the inline/sealed boundary. A cluster inline in the base has no base page extent at its top-node path and must be written when sealed. For a retained page, equal covered content at the same entering path fixes the prefixes, slots and external-child paths. Its retained descendants therefore occupy their corresponding base paths recursively. Equal content at another path supplies no ownership claim. Physical disjointness still applies to the entire reachable graph, including skipped descendants; the existing cold validator marks every extent cell (`src/detent_local/paged_graph_validator.cc:265`). The boundary fixture asserts an equal-content write beside a retained occurrence (`docs/design/dense-pages-model.py:1526`), but neither execution nor an actual digest-global reuse revert check is present.

2. **DP-2: Design contract closed; byte fixtures and lifecycle proof open.** D3 fixes every reference field, DTROOT03's version/length, both retained zero ranges and the complete reserved tail [225,320). It defines absence as exactly 65 zero bytes and derives the empty commitment from the exact non-NUL ASCII domain (`docs/design/dense-pages.md:84`). The root counts and absent tree must agree; empty keeps its cursor/profile. The nonempty inequalities also admit the one-watermark case: keys, height, pages and segments are 1, with length and page bytes 79. The retained root offsets agree with the current encoder (`src/detent_local/paged_layout.cc:259`). Empty packing and the commitment function exist in the model (`docs/design/dense-pages-model.py:759`, `:1446`); it has no DTROOT03 encoder. Exact root/reference bytes and empty restart/delete-last/add-first cases remain K2 work.

3. **DP-3: Design contract closed; validator proof open.** D4 binds reference length/keys/height to the reached header on first touch and hits; D9 requires the same in graph validation (`docs/design/dense-pages.md:97`, `:102`, `:174`). Replay uses a normal sealed child's `(length - 64, height - 1)` cluster, excludes self-sealed pages above C from inline candidates, and rejects zero heights and arithmetic overflow. Together with the child's own canonical validation, these supply the induction premise.

   A warm skip inherits D7's corresponding-path identity and requires the same extent, digest and validated summaries under the retained base lifetime. Preserve the existing context's descriptor/directory/storage checks as well as its entering prefix (`src/detent_local/paged_contextual_reuse.cc:38`; `src/detent_local/paged_warm_validator.cc:339`). An equal digest in a new parent cannot supply that proof. The model's false-summary probes pass altered arguments directly to `PageReader.page` (`docs/design/dense-pages-model.py:1483`); they do not forge an external entry, recompute a parent digest or exercise a competing seal choice. Those checks remain K4/K6 work.

4. **DP-4: Design obligation recorded; read-path proof open.** The execution contract carries the accepted S3b bounded-read/SourceFailure default through every visit, requires exact page starts and bounds traversal progress (`docs/design/dense-pages.md:378`). D4 and Limit 3 retain the residual for framing-valid body mutations (`:102`, `:254`). This is consistent with unauthenticated placement and avoids claiming hit-path body integrity. The separate verified-mapping mutation tests remain K8/K9/K13 obligations.

The design separates placement-free identity from T8's derived-id dependency, defines page/pack/metadata accounting, preserves resumable admission/cancellation/yields, and fixes the explicit churn inputs (`docs/design/dense-pages.md:217`, `:379`). These obligations support implementation.
