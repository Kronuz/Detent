## CL-2: one ownership protocol

Today, file-only `acquire_owner(bool)` and directory-only `acquire_directory_owner()` lock different inodes and can both succeed on one directory. Treat mixed legacy owners as unsafe. A process taking both locks excludes either legacy mode, but a file-only old process and a directory-only old process still do not exclude each other. If the two products address one directory during rollout, a remaining file-only Detent writer still fails to exclude a directory-only strata writer. The default recommendation is `both` for strata too; its proposed format-based exception is evaluated below.

Use one canonical `acquire_owner(OwnerLockOptions)` implementation. Take the directory lock first, then `owner.lock`, and release in reverse. Preserve Detent's explicit exclusive-create versus existing-open policy, zero-length 0600 file and journal bootstrap accounting. Carry the selected protocol through Journal-owned locks as well as direct `StorageSession` calls. Retain ownership through outstanding original completions. Unsupported directory locking fails closed; there is no silent file-only fallback. This can reject a filesystem whose file lock worked but whose directory lock does not, so qualify that capability before deployment.

The old bool and directory entry points remain source-compatible forwarding presets during deprecation. Do not silently make the old directory-only call create a file. Strata needs an explicit owner-file bootstrap policy for existing directories. Unify EINTR handling and unsupported/busy errors, unwind partial acquisitions and descriptor state on failure, and avoid recursive base-IO compatibility forwarding. Test IO must model supported exclusion or report an unsupported capability, never claim success with a no-op owner lock.

Before either consumer changes its production protocol, test every `file/directory/both` pairing with separate processes, in both first-holder orders, through old and new APIs and through shared and distinct IO objects. The legacy file/directory pairing remains an unsafe control; every pairing involving `both` must exclude the competing owner. Reacquisition through one IO must not create independently releasable aliases. Internal acquisition order always stays directory then file. Include partial failure, EINTR, unsupported locks, create/recover, owner lifetime through IO completion and existing symlink/trust refusals on macOS, Linux and FreeBSD. Keep directories under one operational ownership protocol until the migration is qualified; this document alone changes no deployed exclusion.

## Strata follow-up: directory-only ownership

Strata's [response](https://github.com/Kronuz/cpp-libraries/blob/main/docs/reviews/consolidation-2026-10-19.md#responses) retains directory-only ownership because format 13 removes `owner.lock`, pre-lock binaries refuse the new format, and the two products use separate directories. Accept directory-only when that exclusion covers every mutable entry point. Different products need not use identical locks on disjoint directories. The unified library API and Detent's `both` migration can proceed independently.

The current format argument does not cover fresh or interrupted creation. At strata `06a730ba9ca086036e55bfdde2f2d3b4354c345b`, `include/strata/index.hh:2291` takes the directory lock and calls `clear_uncreated()`. Its `uncreated()` predicate accepts unrecognized names, including `owner.lock`, and permits the first metadata file and temporary manifest. `clear_uncreated()` then deletes recognized residue. The pre-D2 creator at `582d6dd2ac84c374be3cd39a6d9fc2c868db0afd`, `include/strata/index.hh:339`, holds only the file lock before that same cleanup and first commit. Both can enter before a committed manifest supplies a version to reject. The existing T5b test starts with committed `manifest-2`, so it does not exercise this case.

Require a process test for an old file-only creator held before first-manifest publication while a new creator attempts the directory, and the reverse order with the new deferred creator held before publication. Include interrupted-create residue and unchanged bytes after refusal. Refusing an already-present `owner.lock` can guard one order but cannot alone prevent an old process creating that file after the new process's check. Directory-only remains conditional on an enforceable exclusion of old creators during create/recreate, or a source-level mechanism proven to exclude both orders. No blanket claim that the unsafe pairing is impossible is accepted yet. Unsupported directory locking under a consumer's warning policy also does not establish exclusion.

## Strata follow-up: node-wide retained usage

Keep `RetainedStatePolicy` and consensus's `RetainedUsage` per group. The latter counts retained log entries and payload bytes; it is not total node memory. Host pools own node-wide admission, lifecycle and authoritative totals across consensus groups, checkpoints, queued operations and transports. Consensus should expose per-group usage suitable for reconciliation, with its units and sampling boundary stated. A convenience aggregate is observational and must not become a second admission ledger. Summing group policy ceilings gives a capacity bound, not current usage; summing separately sampled group gauges is not an atomic node snapshot. No node-wide consensus accounting mechanism is requested.
