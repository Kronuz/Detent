# Local image format, version 1

The Stage 4 local image implementation has a dynamically sized, immutable byte region and a separate selected-generation descriptor. It is available through `detent::local_view` and `detent::local_builder`; the existing agent and CLI still use their legacy shared-memory path until publication and refresh integration is complete.

## Encoding

All integers are explicitly encoded in big-endian order. The image contains a 192-byte header, 24-byte namespace rows, 48-byte record rows, 24-byte override rows, and a dense string region. Region offsets are canonical and checked with overflow-safe arithmetic. The default image admission ceiling is 256 MiB, with independent limits of 500,000 records, 4,096 namespaces, 128 MiB of strings and 256 overrides per definition. These limits describe image bytes and logical counts; they do not establish an aggregate construction-memory budget.

The header binds the complete scope Cursor and semantic Profile. Namespace rows carry their revision watermark. Records carry their namespace index and key revision, followed by the complete boolean or integer definition. Override rows encode a forced boolean or a rollout percentage. Namespaces, records and each definition's overrides must be strictly ordered and unique. Every string is consumed exactly once in canonical row order. Reserved fields must be zero.

The 176-byte `DTSELECT` descriptor contains its format version, a nonzero 16-byte generation identity, image length, SHA-256 checksum, complete Cursor and Profile. Filenames derive only from the hexadecimal generation identity: `generation-<32 hex digits>.image` and its separate `.lease` file. Knob names never become filesystem paths. The descriptor is named `selected`.

## Validation and ownership

`ImageValidator` retains an opaque immutable-byte lease. It charges row and byte budgets before validating each row and exposes a `ReadView` only after all regions and definitions validate. Namespace watermarks cannot exceed the Cursor revision, and key revisions must be positive and cannot exceed their namespace watermark. An optional expected Cursor requires the same identity and a revision at least as recent.

`open_generation` runs on startup or a refresh worker. It opens the directory and descriptor without following symlinks, checks regular files and ownership, and acquires a shared nonblocking kernel lock on the separate generation lease before opening the image. A lease unlinked during acquisition causes a bounded retry. Files must have exactly one link and cannot be writable by group or other users. The configured runtime directory and its ancestry must be trusted; this function does not authorize the publishing service account.

The reader checks the exact file length and descriptor checksum, validates all rows, and retains the mapping, image descriptor and shared lease descriptor through every copied `ReadView`. Cleanup must acquire an exclusive nonblocking lock on that same lease file before removing a retired image. The publishing service must never modify or truncate a sealed image. Recovery and `GenerationReader::refresh()` perform filesystem work on their caller; invoke them on the startup/configuration worker, outside application lookup threads.

`GenerationReader` serializes refreshes and installs a fully validated root under a brief mutex. `read_view()` only copies the installed retirement handle under that mutex; it performs no filesystem or networking work. Failed refresh preserves the previous view. Configured authority identity, installed revision and directory device/inode identity prevent silent scope changes, rollback or directory replacement; identical cursors with different image checksums, lengths or profiles are rejected. A trusted identity transition requires a separately configured reader. Root retirement occurs outside the acquisition lock and mappings retain their existing worker-side cleanup mechanism.

The focused reader fixture checks concurrent acquisition during refresh, configured-scope rejection, unchanged-descriptor detection, failed-refresh retention and usable pinned roots after directory paths disappear. It passes natively, under ASan/UBSan and fully instrumented TSan, on Linux and FreeBSD. SDK overlays and the actual managed agent remain separate integration work; this library test does not establish fleet readiness.

`ReadView` performs binary searches over validated rows and observes one complete generation throughout its lifetime. Its lookup path has no explicit filesystem or network calls. Boolean evaluation preserves the existing full-name SHA-256 rollout semantics, including forced switch precedence and per-switch rollout percentages. The shared hash helper streams the full knob name, NUL separator and hash value directly into SHA-256. In the [allocation benchmark](../benchmarks/hash-allocation-measurements.json), 100,000 calls with a 128-byte hash value change from 100,000 input-buffer allocations to zero while preserving the result sum. Three elapsed-time samples overlap; this establishes allocation removal, not a service latency or power improvement. Error results own diagnostic strings.

`ImageBuilder` borrows a `ValidatedSnapshot` through a shared owner. Counting, buffer initialization, row construction and integrity hashing advance through caller-supplied budgets. The output and descriptor become available only after sealing. It reserves a complete image buffer from the snapshot’s shared storage account before allocation. Original-completion publication and recovery are implemented below; retained-generation accounting remains pending.

## Construction measurements

The [local image benchmark](../benchmarks/local_image_bench.cc) forms 500,000 ordered definitions in one namespace: one quarter integers and three quarters booleans with both a global percentage and a per-switch percentage. The [three fresh-process samples](../benchmarks/local-image-measurements.json) produce a 14,233,697-byte wire object and a 41,000,219-byte local image. Image construction takes 296–304 ms over 119,383 budgeted turns; the largest observed turn is 571 µs. Validation takes 84–93 ms. Across 100,000 preconstructed keys permuted through the 125,000 integer records, lookups take 143–145 ms in total.

Peak RSS is 139.6 MB, including the retained wire object, decoded definitions, complete image and prepared query strings. This corpus differs from the codec comparison workload, so its RSS is not a before/after comparison. The benchmark excludes mapping, publication durability and cleanup. It does not establish sustained refresh throughput, tail latency or an aggregate retention budget.

## Publication implementation

`ImagePublisher` owns the stable backend owner lock and retains the caller's opaque admission lease through accepted completion jobs. It prepares the empty generation lease, immutable image and descriptor in that order, using `ImagePreparation` for each file. It then uses `ImagePublication` to replace `selected` and synchronize the directory. The confirmed published Cursor advances only after both publication originals succeed. A failure after publication submission fences the publisher, preserves potentially selected files and requires recovery.

The native and macOS sanitizer publication suites, Linux and FreeBSD suites inject failures at each of the thirteen original IO steps for a small image. A post-replacement directory-sync failure leaves the complete new image readable while retaining the previous confirmed Cursor and fencing subsequent publication. A held original retains the owner lock and admission lease after the publisher object is destroyed. These tests use synchronous driving of the same operations that native completion owners will accept; they do not qualify process-kill recovery.

Publication is built when `kronuz::completion` is available from reviewed cluster sources. With `DETENT_BUILD_MANAGED_AGENT=ON` and `DETENT_BUILD_DISTRIBUTOR=OFF`, configuration imports only the cluster library's standalone `completion` subdirectory, enabling durable publication without its bus, consensus or HTTP server targets. Four reception/TLS/reader fixtures pass in this agent-only configuration. The `detent_local_view` target also builds with both options disabled; its dependency graph links only the core semantic library and resource support. Complete pipeline admission and production integration remain open.

`RecoveredGeneration` is minted only by the file reader. It binds the validated view and exact descriptor to a retained storage directory descriptor and its device/inode identity. A recovered publisher requires that identity to match its POSIX backend; a copied descriptor from another directory cannot substitute for validation of that directory's image. Recovery starts with no confirmed Cursor. Original completion jobs reopen `selected`, check its exact size and descriptor equality, and synchronize the directory before confirming the recovered Cursor. Every recovery error fences the publisher. Starting without a recovery capability while `selected` exists is rejected.

Recovery tests inject failures at each of its four original steps, reject a stale capability after `selected` changes, and reject a descriptor copied into a different directory without the referenced image. The existing agent/SDK path has not yet been connected to these operations.

Recovery assumes generations were created through the sealed publication protocol: image and descriptor content passed their file-sync barriers before descriptor replacement. Repeating DirectorySync confirms the namespace outcome after uncertain replacement; a checksum-valid arbitrary file cannot prove that publication history.

Closing or cancelling an active recovery suppresses Cursor confirmation. Each accepted operation retains its backend, owner lock, storage capability, reader lease and admission through terminal settlement. Closing also prohibits future publication. Cancellation before an original is submitted stops that job; after replacement submission, the publication operation settles its required barrier but confirmation is suppressed and recovery is required before another candidate. Driver submission, cancellation and coordinator advancement must be serialized on the owner lane.

The final publication suite holds each recovery original across destruction, tests close immediately before and after its final directory-sync completion, and tests cancellation around descriptor replacement. It passes on macOS, Linux and FreeBSD and under macOS ASan/UBSan. The complete native build and all 55 registered tests pass with this component. Actual resource admission and leased generation cleanup remain open.

## Storage admission foundation

`distribution::StorageLedger` grants move-only byte tickets before allocation. `PagedStorage` keeps text and future flat rows in stable pages with intrusive metadata, charging each full page (including its header and alignment) until the allocation is freed. Allocation failure rolls back the ticket. Retirement releases one page per call and forbids further allocations once it begins. The concurrent ledger must outlive its pages and outstanding tickets; each page arena remains single-owner.

The storage test covers quota exhaustion before upstream allocation, allocation failure rollback, stable addresses across page growth and ownership transfer, alignment, arithmetic overflow, and incremental refunds. Snapshots and deltas now use this mechanism for retained rows, text, override ranges and touched-index scratch. Completion-job admission still requires integration. Its metric covers requested upstream capacity; allocator metadata, allocator caches and whole-process RSS remain separate measurements. Disk admission and lease-protected generation cleanup remain pending.

`StableRows<T>` adds a three-level directory for trivially copyable wire rows. Indexing has fixed depth, row blocks and directory nodes share the page account, and growth never copies an existing index or row. `TextRef` borrows contiguous immutable bytes copied into the same arena. These references require the arena owner to remain alive. Tests traverse 70,000 rows across directory boundaries, preserve row and embedded-NUL text references through growth, and inject quota and upstream allocation failures at each initial directory/block allocation. Removing a row retains its physical page charge. These storage tests pass on macOS, Linux and FreeBSD, and under macOS ASan/UBSan.


## Decoded wire ownership and measurements

The unreleased distribution C++ API now exposes `StableRows`, borrowed `string_view` keys/names and `WireDefinition` values. A `WireBoolDef` stores scalar defaults and an offset/count range into the owning update's override table; `snapshot.overrides(flag)` or `delta.overrides(flag)` returns a borrowed range. Keep the validated update alive while retaining row, text or override references. Validated updates are move-only, and moving invalidates the source Cursor. Core `BoolDef`, `Client`, authority storage and the serialized wire/image formats are unchanged.

`Limits::storage_bytes` bounds requested row/text/index page capacity per decoded update (256 MiB by default). Page capacity and allocation hooks are configurable through the same limits. `storage_capacity()` and `peak_storage_capacity()` report admitted capacity. Failed growth fences the decoder; `discard()` invalidates the update immediately and releases pages using byte credits across turns, refunding capacity only after each page is freed. Tests inject allocation failure at every page acquisition in both fixtures, verify retained capacity through moves, and exercise zero and just-insufficient quotas. Decoder, builder and publication suites pass on macOS, Linux and FreeBSD, and under macOS ASan/UBSan.

The [paired measurements](../benchmarks/wire-storage-measurements.json) rebuild the previous decoder/builder at `dc7f34f` and run the same instrumented benchmark sources in three fresh processes per version. The 500,000-record snapshot decodes in 199–206 ms versus 362–382 ms before, with 56,139,904 bytes of admitted row/text/index capacity. Peak RSS ranges overlap (135.6–139.6 MB after, 136.3–139.5 MB before), so these samples do not establish a memory saving. The 100,000-transaction sparse delta decodes in 40–51 ms versus 63–68 ms before and admits 17,117,424 bytes. All snapshot lookup oracle sums remain 24,999,700,000.

Snapshot retirement totals 15–36 ms after versus 35–39 ms before, but the largest measured retirement turn increases to 2.53 ms (0.694 ms before). Fixed page sizes bound release work units; they do not guarantee wall-clock callback latency. These samples do not identify whether the tail comes from freeing memory or scheduling. Retirement belongs on the build/cleanup workers. Fixed control owners, lexical/scope buffers, complete pipeline admission, mapping debt and asynchronous retirement integration remain outside this row-accounting guarantee. No service throughput, infrastructure cost or power saving is claimed.


`Limits::storage_account` optionally shares a concurrent `StorageLedger` across decoded updates. Each update retains the account through its own physical page lifetime, while `storage_bytes` still enforces its per-update ceiling. Per-update capacity counters stay separate from aggregate account counters. Admission uses atomic grant/refund operations and reports quota exhaustion as `StoragePressure`, distinguishable from schema failures while preserving `length_error` handlers. A pinned validated base therefore remains charged when a second decoder fails admission or is destroyed.

The shared-account tests fill a budget just below two complete fixtures, reject the second candidate, dispose its admitted prefix, and verify that the base remains charged. They destroy the first decoder before checking retained ownership and verify that retry succeeds after the base pages are actually released. Concurrent ticket tests exercise eight grant/refund threads. This extends the row-page guarantee across owners; control objects, mapping debt and disk artifacts still need their own admission integration.

### Charged image-write buffers

`distribution::OwnedBuffer` admits its complete backing capacity, including the intrusive page header, before allocation. Initialization advances within that fixed capacity; sealing removes mutable access. `ImageBuilder::bytes()` now returns `shared_ptr<const OwnedBuffer>` rather than `shared_ptr<const string>`. This is a change to the unreleased local-image API; the existing Core, Client, CLI, binary wire and local-image formats retain their contracts.

The builder uses the validated snapshot’s storage account, so retained rows and the candidate image compete for the same quota. The publisher also charges the temporary descriptor body to that account. The compatible completion-library byte-view overload retains each immutable buffer directly, without copying it into a string. Accepted originals retain the buffer and its charge through the final authentic preparation barrier, even if the initiating builder and publisher disappear. Physical release precedes the quota refund.

Tests reject an image whose quota is one byte short after retained rows are counted, verify that the failure leaves the row charge intact, and exercise an accepted image write after all initiating facades are destroyed. All targets build, and all ten distribution/local-image tests pass on macOS. The storage, builder and publication tests also pass under macOS ASan/UBSan and on Linux and FreeBSD. This does not yet bound fixed control allocations, mapped generations or disk artifacts. An image buffer’s standalone last owner can still call `free` synchronously on its build/IO worker. The `ReadView` ownership path now retires its root and byte lease on the cleanup worker, as described below.

Receive framing now shares the same optional storage account. Encoded bodies, sealed decoded output and the fixed zstd workspace remain charged through their physical lifetimes. The receive tests cover pressure before encoded allocation and during compressed overlap, decoder fencing, a caller retaining one fragment while the next fails admission, output surviving decoder destruction, and empty compressed/uncompressed final fragments. See [the framing contract](DISTRIBUTION_ARCHITECTURE.md#framing-and-bounded-parsing) for the unreleased receive API change.

### Inline lexical scratch

Snapshot and delta schemas bound individual lexical fields at 200 bytes. They now use an inline MessagePack token buffer instead of allocating a string per token. Only the populated prefix is copied; returned tokens own that prefix. The generic MessagePack `Decoder` and `Token` retain their string-based API. Oversized fields are rejected from their declared length before payload copying, and tests cover fragmented 200-byte strings, embedded NUL bytes, independent token copies and fencing at 201 bytes. Fixed decoder state still needs its own control-allocation charge.

The [paired 500k measurements](../benchmarks/inline-token-measurements.json) rebuild the previous parser at `70e3df5` and use the unchanged image benchmark in three serial fresh-process pairs after qualification builds finish. Decode time is 186–190 ms with inline scratch versus 200–203 ms before; all lookup oracle sums remain 24,999,700,000. Peak RSS ranges overlap, and no fleet throughput, latency, power or cost result is implied. The MessagePack, snapshot, delta, builder and publication suites pass on macOS, Linux and FreeBSD and under macOS ASan/UBSan.

### Accounted buffer controls

`StorageAllocator<T>` charges the complete upstream request, including its own aligned header, before allocation. It supports standard container growth and `allocate_shared`, accounting for replacement overlap and actual library control-block size rather than estimating it. Its header keeps the account alive, and deallocation refunds only after the upstream release. Constructor and allocation failures roll back admission. Allocator metadata and process RSS remain outside the requested-capacity metric.

`make_owned_buffer` uses this allocator for the buffer object and shared control block. Image/descriptor builders and receive/decompression buffers use this factory. Payload page counters remain distinct from aggregate account usage: even an empty owned buffer has a charged control allocation, and a weak owner can retain that control charge after the payload is destroyed. Tests exercise weak retention, container growth overlap, constructor failure, allocation failure, overflow, and quota rejection before upstream allocation. Other decoder, validator and completion controls still require this integration; last-reader retirement will use intrusive ownership to avoid freeing a shared control block on the lookup caller.

All targets build and all 58 native tests pass after the buffer-control integration. The storage, receive-framing, builder and publication suites also pass on Linux and FreeBSD and under macOS ASan/UBSan.

### Last-reader retirement

`ReadView` now owns its root through an intrusive handle. Its final release publishes the root’s already-admitted retirement node, sends a nonblocking wake, then publishes readiness. It does not destroy the root, release its byte lease, unmap its image, close its generation lease or free a shared-owner control block on the reader’s thread. The worker cannot read an unpublished chain link or reclaim a node before readiness. An early wake is covered by a bounded periodic poll while a handoff remains incomplete; an otherwise idle runtime waits for its wake signal. No hard wall-clock release guarantee is claimed.

The reusable `detent::resources` target has no Detent model, HTTP, codec or Asio dependency. `RetirementRuntime` owns one fixed pthread, a two-descriptor wake pipe, and a charged fixed registry of at most 32 domains (eight by default). Registry, domain-control and owner allocations are charged before exposure. The configured thread stack is 1 MiB by default and is reported separately as a fixed native baseline; OS guard pages, thread implementation metadata and allocator caches are outside managed heap capacity. Domain replacement does not create another worker.

Closing a domain rejects new owners while retaining admitted owners, queued handoffs and cleanup steps in its registry slot. Existing views remain usable and copyable. Parent owners can retire child handles or pages incrementally. The slot is released after physical cleanup, and an explicit drain token permits an application-shutdown wait. Waiting or joining from the cleanup worker is rejected. Permanent runtime shutdown stops domain registration, drains domains and joins the fixed worker from the application owner. The application must keep the runtime alive for its admitted views and authentic originals; a pinned view can postpone drainage indefinitely. This worker does not replace the native/fallback disk completion driver.

`ViewLimits::retirement_domain` selects an application-owned domain. Standalone readers otherwise share a process-lifetime default worker, a 4 MiB root-control account and a 4096-root limit. The default worker is intentionally retained until process termination; applications requiring ordered teardown supply an explicit domain. Closing a view no longer promises an immediately available exclusive generation lease: the lease remains held until actual worker cleanup.

Qualification pauses a last releaser after mailbox insertion, consumes its wake before readiness, and verifies that neither the node nor its domain drains early. It covers late release after close, accepted-owner retention on another thread, nested incremental cleanup, failed admission/constructors, exhausted registry slots and repeated domain replacement. An actual `ReadView` fixture checks that the final byte lease is destroyed on the cleanup worker after release on an SDK caller thread. Standalone resources and view integration pass macOS TSan; their changed source is instrumented, while the view fixture links existing uninstrumented Core/hash dependencies. All targets build and all eleven distribution/local-image suites pass natively. Retirement, view, builder and publication suites pass on Linux and FreeBSD and under macOS ASan/UBSan.

Mapped-byte tickets, decoder/completion control integration, disk admission and lease-protected generation reclamation remain open. This mechanism qualifies reader-root retirement rather than completing the full resource subcomponent or Stage 4.

### Mapped-capacity admission

`ViewLimits::mapping_account` optionally supplies a shared account for mapped virtual bytes. Standalone readers use a separate 512 MiB process-lifetime mapping account. Recovery rounds the validated image length up to the OS page size and admits that full capacity before `mmap`. This counter describes virtual mappings, not resident memory, physical disk blocks or managed heap capacity. Separate mappings of the same image each consume capacity; copies of a `ReadView` retain its existing mapping.

Mapping metadata and the opaque lease holder use the retirement domain’s heap account. The mapping is an intrusive retirement owner: final reader release schedules root cleanup, then mapping cleanup performs `munmap` and closes each descriptor on the fixed cleanup worker. Mapping capacity is refunded only after successful `munmap`. Failed cleanup retains ownership and charge on a bounded retry queue; it does not report successful drainage. Failed acquisition also retires its admitted resources. Directory control allocation precedes opening its descriptor and uses the same heap account.

Tests cover zero and one-byte-short mapping quotas, page-rounded charges, an exhausted account with a pinned base, retained copies, retry after actual unmapping, and usable views after domain close. Decoder/completion control integration, disk admission and lease-protected generation reclamation remain open; this completes mapping admission rather than Stage 4.

Mapping, directory-ownership, retirement and publication suites pass on macOS, Linux and FreeBSD and under macOS ASan/UBSan. The mapping-view and standalone retirement fixtures also pass TSan; the mapping fixture instruments changed resource/view source and links existing uninstrumented Core/hash dependencies. The retirement fixture keeps an unsuccessful cleanup charged while another domain drains, then permits the original cleanup to complete. No process-wide RSS or callback-latency guarantee is inferred from these capacity checks.

## Managed ownership records and reader upgrade

The pure codecs in `detent_local/ownership.hh` implement the immutable 64-byte `DTSTORE1` storage identity and 128-byte `DTLEASE1` generation ownership record specified in the [disk lifecycle blueprint](DISK_LIFECYCLE_ARCHITECTURE.md#ownership-records-and-reader-compatibility). They enforce exact lengths, versions, nonzero identities and SHA-256 checksums. Lease ownership binds the intended image length and checksum independently of current admission quotas. The SDK target gains no completion, journal or networking dependency.

Readers accept existing empty leases and managed records. A managed lease requires a trusted, singly linked, non-writable-by-others `storage.meta` file, and its storage identity, generation identity, image length and checksum must match the selected descriptor. After acquiring the shared lease, the reader matches its held inode against the directory name before opening the image, retrying a removed/replaced anchor. Full image integrity and semantic validation remain required.

**Upgrade readers before enabling managed publication.** Older SDK binaries require empty leases and cannot read these managed generations. This reader extension preserves `DTIMAGE1`, the 176-byte selected descriptor and generation filenames. Existing publishers still create empty leases; managed publication and reclamation remain unimplemented. Empty legacy leases are readable and provide no automatic-deletion authority.

Independent Python `struct.pack`/`hashlib` vectors qualify both codecs. Tests corrupt every byte, reject truncated/overlong records and checksum-valid unsupported fields, reject zero identities and undersized images, and verify quota-independent length encoding. Reader fixtures cover legacy/managed compatibility, missing/corrupt/unsafe identity files, symlinks, hard links and each selected-field mismatch. Five focused ownership, reader, view, directory and publication suites pass on macOS (5.79 seconds), Linux (0.38 seconds), FreeBSD and macOS ASan/UBSan (6.14 seconds). These are reader and codec gates; complete lifecycle qualification remains open.

## Logical disk accounting foundation

`DiskLedger` separately counts logical named bytes, top-level entries and canonical generation anchors, with outstanding reservations and peak overlap reported separately. A managed family reserves `image length + 128 + 176` bytes, three entries and one generation before its first Create. Existing census usage is retained in full even above smaller current limits; additions fail and proved reclamation can still reduce that debt. The currency reserves no physical filesystem blocks.

Its two-slot reservation registry contains no dynamically growing history. Permits have monotonically increasing identities; reuse rejects stale permits. No permit destruction refunds disk. Unstarted cancellation releases a reservation explicitly; accepted originals retain it until matched completion and proved settlement. The application must establish namespace observations, required directory barriers and handle closure before calling settlement or reclamation. Oversized effects fence the ledger while preserving its outstanding reservation.

Tests distinguish first publication from replacement, retain both descriptors through the pre-Rename peak, delay old descriptor credit until explicit settlement, exercise each quota dimension one unit short, and preserve maximal unsigned over-quota debt without subtraction underflow. They cover pending originals, stale permits, registry exhaustion, uncertain effects and erroneous credits. One hundred thousand successful reserve/complete/settle/reclaim cycles observe zero global allocations. The accounting fixture passes on macOS, Linux and FreeBSD and under macOS ASan/UBSan. This is the accounting foundation; it does not yet connect census, publication or GC proofs to filesystem effects.

## Streaming logical census

`InventoryOperation` performs a quiescent, completion-driven census through one cursor, a 256-byte name buffer and eight fixed diagnostic samples. Its coordinator must pause namespace mutations and settle prior originals. Each returned name receives one no-follow metadata inspection. Checked counters retain all logical named bytes and entries, count syntactically canonical lease anchors even when malformed, and report canonical payload names separately. This pass establishes accounting, not ownership records, selected-root validity or deletion authority.

Missing entries, invalid basenames, arithmetic overflow, exhausted work allowance, unexpected directories and IO errors reject the complete report. Work allowance is independent of disk quotas. Foreign, unsafe, symlink, special and multiply linked entries remain counted and preserved; directory contents are never recursively inferred from `st_size`. Failure and cancellation still settle accepted originals and consume an authentic cursor-close result before reaching their terminal state. A secondary close error preserves the primary census failure.

The synthetic fixture scans one and 100,000 entries with one cursor allocation in each case and exactly one metadata inspection per entry. At initial census revision `d3f9f89`, admitted job/state controls, including fixed scratch and diagnostics, occupied 2,902 bytes on the measured macOS and FreeBSD libc++ toolchains and 2,886 bytes on Linux/GCC 13. With reusable-collector state at `15d12a9`, these controls occupy 2,934 bytes on Intel macOS, unchanged between one and 100,000 entries. Those controls complete with their common ledger saturated and retain weak-control charges until actual release. Session/backend/cursor/queue capacity and native/runtime resources are additional. These figures do not measure process RSS, real-filesystem throughput or a fleet efficiency gain.

Real filesystem fixtures account foreign files, hard links, symlinks and a malformed zero-identity anchor without following or deleting them. A native queue retains a cancelled scan after its initiating facades disappear, then retains cursor closure through authentic settlement. Initial census and publication suites pass on macOS (4.95 seconds), Linux (0.44 seconds), FreeBSD (0.44 seconds) and macOS ASan/UBSan (4.43 seconds). The inventory/session/native-driver chain also passes fully instrumented focused TSan.

`CollectorControls` now preadmits eight closed lease files, one scratch file and one cursor, shared serially by census and future GC. Reusable census makes 100 real passes with no additional managed allocation calls while its account is saturated. At `15d12a9`, the collector/session/backend/queue/census fixture occupies 5,527 admitted bytes on Intel macOS, including ledger headers. Its session close flag adds eight bytes to the earlier 5,519-byte collector measurement. Claim release requires handle closure and preceding-original retirement; it grants no disk credit. Owning sessions and bounded proof reads are qualified in the [disk lifecycle reference](DISK_LIFECYCLE_ARCHITECTURE.md). Identity bootstrap, retained managed publication and reclamation remain integration work.

### Exact-base delta and progress construction

`ImageBuilder` also accepts a shared validated delta/progress value and a `RecoveredGeneration`. A private source reads namespace, record and override rows from the validated mapping while retaining its shared kernel lease and directory identity. The complete base Cursor and profile must match before construction starts.

Scratch pages use the validated update's storage account. Construction gathers mutation references, performs stable bottom-up merge passes, collapses repeated keys to their final transaction, and merges the pinned base once. Untouched key revisions remain unchanged; changed keys and namespace watermarks use their transaction revisions. Deletes remove live definitions. Progress emits the same state with the new global Cursor. Namespace and final record limits apply before output allocation.

Work budgets cover merge phases and scratch retirement, including one-byte budgets. The existing count, initialization, row emission and hashing phases produce the same canonical image as snapshot construction. `discard()` terminates a failed or cancelled builder and retires scratch/output ownership under the caller's budget. The caller retains validated input until destroying the builder, then drains the input's own disposal cursor.

Publication checks `base_descriptor()` and `base_directory_identity()` against the store's actual selected generation before accepting a delta/progress image. Cancellation acknowledgement and an equal revision number cannot substitute for that evidence. Snapshot construction keeps its existing constructor and publication contract.

Focused tests cover repeated-key updates across 17 transactions, deletion/reinsertion, progress preserving state and revisions, exact-base rejection, saturated allocation admission and merged-record rejection. An independently spelled snapshot tuple stream supplies the final byte/checksum equivalence oracle. The three focused suites pass on macOS, Linux and FreeBSD, with ASan/UBSan (1.27 seconds) and TSan (5.79 seconds). The five native builder/publication regression suites pass in 85.87 seconds. These fixtures do not establish delivery throughput or production integration.
